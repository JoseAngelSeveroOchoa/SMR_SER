    UT2_1 – Servicio DNS

    ¿Qué es DNS?

    El DNS (Domain Name System) traduce nombres de dominio a direcciones IP.

    👉 Ejemplo:

    google.com → 142.250.184.78

    📌 Idea clave:
    DNS evita que tengamos que memorizar direcciones IP.

    Conceptos básicos

    🔹 Dominio vs Host

    Concepto Ejemplo
    Dominio .com, google.com
    Host www, mail, pc1

    🔹 Host

    Un host es cualquier dispositivo conectado a la red: - PC - Servidor - Router - Impresora

    👉 Cada host tiene: - Nombre - Dirección IP

    FQDN (Fully Qualified Domain Name)

    Ejemplos:

    www.google.com . mail.yahoo.com. smtp.severoochoa.com.

    ⚠️ El punto final (.) indica la raíz del DNS

    Configuración básica DNS

    Windows

    ipconfig /all

    Linux

    cat /etc/resolv.conf

    Archivo hosts

    Antes del DNS se utilizaba un archivo local (hosts.txt).

    📍 Ubicación: - Linux → /etc/hosts - Windows → C:\Windows\System32\drivers\etc\hosts

    📌 Prioridad:

    hosts → DNS

    Historia del DNS

    • 1971–1972 → hosts.txt
    • 1985 → Nace DNS
    • Actualidad → Sistema distribuido

    Conceptos clave

    Base de datos distribuida

    DNS no está centralizado, se reparte en múltiples servidores.

    Zonas DNS

    Contienen los registros de un dominio.

    📍 Linux (bind9):

    /etc/bind/named.conf.local

    Configuración de zonas (bind9)

    Archivo:

    /etc/bind/named.conf.local

    Ejemplo:

    zone "oc.se" { type master; file "/var/lib/bind/db.oc.se"; };

    Archivos de zona:

    /var/lib/bind/

    Registros DNS

    Tipo Función
    A Nombre → IPv4
    AAAA Nombre → IPv6
    CNAME Alias
    MX Servidor de correo
    NS Servidores DNS
    PTR IP → Nombre
    SOA Información de la zona
    TXT Texto (verificación, etc.)
    SRV Servicios y puertos

    Jerarquía DNS

    . (root) └── .com └── google.com └── www

    Niveles:

    • Root (.)
    • TLD (.com, .org, .es)
    • Dominio
    • Subdominio

    Servidores DNS

    Tipos:

    • Root servers
    • TLD servers
    • Autoritativos
    • DNS local (resolver)

    Resolución DNS (paso a paso)

    1. Cliente consulta caché
    2. DNS local consulta root
    3. Root → indica TLD (.com)
    4. TLD → indica servidor autoritativo
    5. Autoritativo → devuelve IP
    6. Se guarda en caché

    Tipos de consultas

    🔹 Recursiva

    El cliente pide la respuesta completa.

    🔹 Iterativa

    El servidor responde parcialmente o redirige.

    Configuraciones típicas

    1. DNS del propio dominio
    2. DNS del ISP
    3. DNS como caché

    Reenviadores DNS

    • Reenvían consultas externas
    • Mantienen caché
    • Reducen tráfico

    DNS inverso

    Convierte IP → nombre

    📌 Usa: - Dominio: in-addr.arpa - Registro: PTR

    Ejemplo:

    80.58.61.250 → www.somtic.net

    Servidores DNS

    Maestro (Master)

    • Editable
    • Fuente principal

    Esclavo (Slave)

    • Solo lectura
    • Sincronizado automáticamente

    Organizaciones

    ICANN

    • Gestiona DNS global
    • Asigna dominios
    • Acredita registradores

    IANA

    • Gestiona zona raíz
    • Asigna nombres y números

    📌 Resumen final

    DNS es: - Distribuido
    - Jerárquico
    - Con caché

    👉 Función principal:

    Nombre → IP
