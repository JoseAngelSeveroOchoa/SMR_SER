    UT2_1 – Servicio DNS

    Introducción al DNS

    Nombres de dominio

    Ejemplos: .org, .net, qualitypixels.net, google.com

    Nombres de host

    Ejemplos: pc1, a112, impresora1, etc.

    Hosts

    Un host es un ordenador, impresora, router, servidor, etc.
    Cada host tiene un nombre de equipo y al menos una dirección IP.

    Configuración de servidores DNS

    Windows

    ipconfig /all

    Linux

    cat /etc/resolv.conf

    Archivo hosts

    Antes del DNS (1971–72) se usaba un fichero local hosts.txt. Ubicación: - Linux: /etc/hosts - Windows: C:\Windows\System32\drivers\etc\hosts

    Historia del DNS

    • 1971–1972: uso de hosts.txt
    • 1985: primera versión de DNS
    • Actualidad: DNS es una base de datos distribuida

    Conceptos básicos de DNS

    Base de datos distribuida

    DNS mantiene una base de datos distribuida de nombres e IPs.

    Ficheros de zona

    Las zonas contienen los registros DNS del dominio.

    Proceso de resolución

    El servidor DNS consulta primero sus ficheros de zona.

    Ubicación de zonas en Linux (bind9)

    Archivo: /etc/bind/named.conf.local

    Configuración de zonas en bind9

    Archivo: /etc/bind/named.conf.local Ejemplo: 

    zone "oc.se" {
  type master;
  file "/var/lib/bind/db.oc.se";
};
    Archivos: /var/lib/bind/

    Contenido de un archivo de zona DNS

    • SOA: registro principal de la zona
    • NS: servidores autoritativos
    • A: nombre ↔ IP
    • CNAME: alias
    • PTR: resolución inversa

    Jerarquía del DNS

    • Raíz ".": gestionada por root servers
    • TLD: .com, .edu, .net, .org, .es...
    • Dominios y subdominios: yahoo.com, instagram.com

    Servidores raíz y TLD

    1. Root servers → conocen a los TLD
    2. Servidores TLD → conocen servidores autoritativos
    3. Lista: https://www.iana.org/domains/root/db

    FQDN

    Ejemplos: - www.yahoo.com. - mail.google.com. - smtp.severoochoa.com.

    Ejemplo de resolución DNS

    1. Root servers indican TLD .com
    2. TLD .com indica servidor autoritativo
    3. Autoritativo devuelve la IP

    Proceso de resolución DNS

    • Cliente DNS: mantiene caché
    • Servidor DNS local: búsqueda recursiva
    • Root & TLD: indican servidores autoritativos
    • Autoritativo: respuesta final

    Configuraciones típicas

    1. DNS del mismo dominio
    2. DNS del ISP
    3. DNS como caché

    Tipos de peticiones

    Recursivas

    El cliente pide resolución completa.

    Iterativas

    El servidor da info parcial o delega.

    Ejemplo búsqueda www.yahoo.com

    1. Cliente consulta caché
    2. DNS ISP consulta root
    3. Root indica .com
    4. .com indica autoritativo
    5. Autoritativo da IP
    6. Caché se actualiza

    Tipos de registros DNS

    A y SOA

    • A: nombre ↔ IP
    • AAAA: IPv6
    • SOA: parámetros de zona

    NS y MX

    • NS: servidor autoritativo
    • MX: servidor de correo

    SRV y CNAME

    • SRV: servicios y puertos
    • CNAME: alias

    TXT

    • Texto asociado al dominio
    • Verificaciones
    • Ejemplo: google-site-verification

    Más tipos

    https://es.wikipedia.org/wiki/Anexo:Tipos_de_registros_DNS

    Reenviadores DNS

    • Reenvían consultas externas
    • Mantienen caché
    • Pueden ser autoridad local

    ICANN

    • Organización sin ánimo de lucro
    • Gestiona IPs, identificadores, DNS, root servers
    • Acredita registradores

    IANA

    • Mantiene zonas raíz
    • Asigna espacio de nombres
    • Supervisa operaciones DNS

    Registradores

    • Actualizan info en servidores TLD
    • Acreditados por ICANN

    Operadores de root servers

    • 12 operadores
    • 13 root servers
    • Info: https://root-servers.org/

    DNS invertido

    • Usa dominio in-addr.arpa
    • Usa registros PTR Ejemplo:
    • A: www.qualitypixels.net → 80.58.61.250
    • PTR: 250.61.58.80.in-addr.arpa → www.somtic.net

    Servidores maestros y esclavos

    • Maestro: editable
    • Esclavo: solo lectura, sincronizado
    • Sincronización automática por red
