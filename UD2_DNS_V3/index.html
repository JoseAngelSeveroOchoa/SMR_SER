    UD2 – Servicio DNS

    1. Introducción

    El DNS (Domain Name System) es un sistema que permite traducir nombres de dominio a direcciones IP, facilitando la comunicación entre dispositivos en una red.

    Por ejemplo, en lugar de acceder a un servidor mediante una dirección IP como 142.250.184.78, los usuarios pueden utilizar un nombre más fácil de recordar como google.com.

    El DNS es un sistema distribuido y jerárquico que funciona a nivel global.

    2. Conceptos básicos

    2.1. Dominio y host

    Un dominio es un nombre que identifica una organización o entidad dentro de Internet, como google.com.

    Un host es un dispositivo concreto dentro de ese dominio, como: - www - mail - ftp

    La combinación de ambos forma un nombre completo.

    2.2. Host

    Un host es cualquier dispositivo conectado a una red: - Ordenadores - Servidores - Impresoras - Routers

    Cada host dispone de: - Un nombre - Una dirección IP

    2.3. FQDN (Fully Qualified Domain Name)

    Es el nombre completo de un host dentro del sistema DNS.

    Ejemplos:

    www.google.com . mail.yahoo.com. smtp.severoochoa.com.

    El punto final (.) representa la raíz del sistema DNS.

    3. Funcionamiento del DNS

    El proceso de resolución de nombres permite obtener la dirección IP asociada a un dominio.

    3.1. Proceso de resolución

    1. El cliente consulta su memoria caché.
    2. Si no encuentra la respuesta, consulta a su servidor DNS local.
    3. El servidor DNS local consulta a un servidor raíz.
    4. El servidor raíz indica el servidor del dominio de nivel superior (TLD).
    5. El servidor TLD indica el servidor autoritativo.
    6. El servidor autoritativo devuelve la dirección IP.
    7. La respuesta se almacena en caché.

    3.2. Tipos de consultas

    Consultas recursivas

    El cliente solicita al servidor DNS que resuelva completamente el nombre.

    Consultas iterativas

    El servidor DNS responde con la mejor información disponible y puede redirigir a otros servidores.

    4. Jerarquía del DNS

    El DNS está organizado en forma de árbol jerárquico:

    . (root) └── .com └── google.com └── www

    Niveles: - Raíz (.) - Dominios de nivel superior (TLD): .com, .org, .es - Dominios - Subdominios

    5. Servidores DNS

    5.1. Tipos de servidores

    • Servidores raíz (root servers)
    • Servidores TLD
    • Servidores autoritativos
    • Servidores DNS locales (resolvers)

    5.2. Servidores maestro y esclavo

    Servidor maestro (master): - Contiene la información original - Permite modificaciones

    Servidor esclavo (slave): - Copia del servidor maestro - Solo lectura - Se sincroniza automáticamente

    6. Registros DNS

    Los registros DNS almacenan la información necesaria para la resolución de nombres.

    Tipo Función
    A Asocia un nombre a una dirección IPv4
    AAAA Asocia un nombre a una dirección IPv6
    CNAME Define un alias
    MX Indica servidores de correo
    NS Define servidores DNS autoritativos
    PTR Resolución inversa (IP a nombre)
    SOA Información principal de la zona
    TXT Información adicional o verificación
    SRV Define servicios y puertos

    7. Zonas DNS

    Una zona DNS es una parte del espacio de nombres gestionada por un servidor DNS.

    Contiene los registros asociados a un dominio.

    7.1. Archivos de configuración en Linux (bind9)

    Archivo principal:

    /etc/bind/named.conf.local

    Ejemplo de definición de zona:

    zone "oc.se" { type master; file "/var/lib/bind/db.oc.se"; };

    Archivos de zona:

    /var/lib/bind/

    8. Configuración básica del cliente

    8.1. Windows

    ipconfig /all

    8.2. Linux

    cat /etc/resolv.conf

    9. Archivo hosts

    Antes de la aparición del DNS se utilizaba un archivo local llamado hosts.txt.

    Ubicación: - Linux: /etc/hosts - Windows: C:\Windows\System32\drivers\etc\hosts

    El sistema operativo consulta primero este archivo antes de usar DNS.

    10. DNS inverso

    El DNS inverso permite obtener el nombre de dominio a partir de una dirección IP.

    Utiliza: - Dominio: in-addr.arpa - Registros: PTR

    Ejemplo:

    80.58.61.250 → www.somtic.net

    11. Reenviadores DNS

    Los reenviadores son servidores DNS que se encargan de reenviar consultas a otros servidores externos.

    Funciones: - Reducir tráfico - Mejorar tiempos de respuesta mediante caché - Centralizar consultas externas

    12. Configuraciones típicas

    • Uso de DNS del propio dominio
    • Uso de DNS del proveedor de Internet (ISP)
    • Uso de servidor DNS como caché

    13. Organizaciones relacionadas

    13.1. ICANN

    Organización encargada de: - Gestionar el sistema de nombres de dominio - Asignar dominios - Acreditar registradores

    13.2. IANA

    Responsable de: - Gestionar la zona raíz - Asignar direcciones IP y nombres

    14. Resumen

    El DNS es un sistema: - Distribuido - Jerárquico - Basado en caché

    Su función principal es:

    Nombre de dominio → Dirección IP
